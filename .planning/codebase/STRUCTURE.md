## Directory Purposes

**`cmd/`:**
- Purpose: Single binary entry point
- Contains: `main.go` only — wires all dependencies and registers all controllers with controller-runtime manager
- Key files: `cmd/main.go`

**`api/v1alpha1/`:**
- Purpose: Custom Resource Definition (CRD) type declarations generated by kubebuilder
- Contains: `*_types.go` files for each CRD, `groupversion_info.go`, `zz_generated.deepcopy.go`
- Key files: `api/v1alpha1/loadbalancerconfig_types.go`, `api/v1alpha1/globalloadbalancerconfig_types.go`, `api/v1alpha1/nodesecuritygroup_types.go`, `api/v1alpha1/vngcloudgloballoadbalancer_types.go`

**`internal/domain/`:**
- Purpose: Shared constants used across the application — finalizer strings, annotation prefix constants, label keys, CRD kind names
- Contains: `domain.go` (constants), `error.go` (domain error types)
- Key files: `internal/domain/domain.go`

**`internal/repository/k8s_repo/`:**
- Purpose: Abstracts all Kubernetes API access (reads/writes to the cluster)
- Contains: `k8s_repo.go` (interface + implementation)
- Key files: `internal/repository/k8s_repo/k8s_repo.go`

**`internal/repository/vngcloud_repo/`:**
- Purpose: Abstracts all VngCloud API calls (load balancers, listeners, pools, certificates, security groups, etc.)
- Contains: One file per VngCloud resource type plus mocks subdirectory
- Key files: `internal/repository/vngcloud_repo/vngcloud_repo.go`, `internal/repository/vngcloud_repo/vngcloud_mocks/`

**`internal/usecase/`:**
- Purpose: Business logic orchestration — each subdirectory handles one controller's reconcile logic
- Contains: Build/deploy/delete operations per resource, status update, validation
- Pattern: Each `*_uc/` package exposes a use case interface consumed by the corresponding controller
- Key files: `internal/usecase/service_uc/service_uc.go`, `internal/usecase/lbc_uc/lbc_uc.go`

**`internal/controller/`:**
- Purpose: controller-runtime `Reconciler` implementations — thin layer that delegates to use cases
- Contains: One `*_controller.go` per controller, `eventhandlers/` subdirectory for Watch predicates/handlers
- Key files: `internal/controller/core/service_controller.go`, `internal/controller/lbc_controller/lbc_controller.go`

**`pkg/`:**
- Purpose: Reusable packages shared across use cases and controllers; contains utilities, config, metrics, annotation parsing
- Contains: Domain-specific helpers (`service/`, `lbc/`, `nsg/`, etc.) plus cross-cutting concerns (`logging/`, `metrics/`, `errs/`, `config/`)

**`pkg/config/`:**
- Purpose: Loads and validates controller configuration from `/etc/vngcloud-load-balancer-controller/config.yaml`
- Key files: `pkg/config/config.go`

**`pkg/errs/`:**
- Purpose: Structured error types including requeue errors with backoff and error-with-metrics wrappers
- Key files: `pkg/errs/errors_requeue.go`, `pkg/errs/error_with_metrics.go`, `pkg/errs/reconcile.go`

**`pkg/k8s/apis/vks.vngcloud.vn/`:**
- Purpose: CRD YAML files embedded in the binary and installed at startup via `InstallAllCRDs`
- Key files: `pkg/k8s/apis/vks.vngcloud.vn/crds/`

**`config/`:**
- Purpose: Kustomize-based Kubernetes manifests for deploying the controller
- Generated: CRD bases are generated; RBAC and deployment manifests are hand-maintained
- Committed: Yes

**`charts/`:**
- Purpose: Helm chart for production deployment via Helm
- Key files: `charts/vngcloud-load-balancer-controller/Chart.yaml`, `charts/vngcloud-load-balancer-controller/values.yaml`

**`test/`:**
- Purpose: End-to-end test suite and shared test utilities
- Key files: `test/e2e/e2e_test.go`, `test/e2e/e2e_suite_test.go`

## Key File Locations

**Entry Points:**
- `cmd/main.go`: Binary entry point — initializes manager, wires repositories → use cases → controllers

**Configuration:**
- `pkg/config/config.go`: Configuration struct and loader
- `go.mod`: Module path `github.com/vngcloud/vngcloud-load-balancer-controller`
- `.golangci.yml`: Linter configuration
- `.mockery.yml`: Mock generation configuration
- `Makefile`: All build, test, generate, and deploy targets

**Core Logic:**
- `internal/domain/domain.go`: Shared constants (finalizers, annotation prefixes, labels)
- `internal/repository/vngcloud_repo/vngcloud_repo.go`: VngCloud API repository interface
- `internal/repository/k8s_repo/k8s_repo.go`: Kubernetes repository interface
- `internal/usecase/service_uc/service_uc.go`: Service LoadBalancer reconcile logic
- `internal/usecase/lbc_uc/lbc_uc.go`: LoadBalancerConfig reconcile logic

**CRD Types:**
- `api/v1alpha1/loadbalancerconfig_types.go`: LoadBalancerConfig CRD type
- `api/v1alpha1/globalloadbalancerconfig_types.go`: GlobalLoadBalancerConfig CRD type
- `api/v1alpha1/nodesecuritygroup_types.go`: NodeSecurityGroup CRD type
- `api/v1alpha1/vngcloudgloballoadbalancer_types.go`: VngcloudGlobalLoadBalancer CRD type

**Testing:**
- `test/e2e/`: End-to-end test suite
- `internal/repository/vngcloud_repo/vngcloud_mocks/`: Generated mocks for VngCloud repository
- `internal/usecase/*/mocks.go` or `*_test.go`: Unit test files co-located with use cases

## Naming Conventions

**Files:**
- Controller files: `<resource>_controller.go` (e.g., `lbc_controller.go`, `service_controller.go`)
- Use case files: `<resource>_uc.go` (e.g., `lbc_uc.go`, `service_uc.go`)
- Repository files: `<provider>_repo.go` (e.g., `vngcloud_repo.go`, `k8s_repo.go`)
- Build/deploy operations: `build_<resource>.go`, `deploy_<resource>.go`, `delete_<resource>.go`
- Test files: `<source_file>_test.go` co-located with source

**Directories:**
- Use case packages: `<resource>_uc` (e.g., `lbc_uc`, `service_uc`)
- Controller packages: `<resource>_controller` (e.g., `lbc_controller`, `nsg_controller`)
- Exception: `core/` for the Service controller, `networking/` for the Ingress controller

**Packages:**
- Package names match directory base names (e.g., directory `lbc_uc` → `package lbc_uc`)

## Where to Add New Code

**New CRD type:**
- Type definition: `api/v1alpha1/<resource>_types.go`
- Run `make generate` and `make manifests` to regenerate deepcopy and CRD YAML
- Embed CRD YAML: `pkg/k8s/apis/vks.vngcloud.vn/crds/`
- Register in `api/v1alpha1/groupversion_info.go`

**New controller:**
- Controller package: `internal/controller/<resource>_controller/`
- Use case package: `internal/usecase/<resource>_uc/`
- Utility helpers: `pkg/<resource>/`
- Wire in `cmd/main.go` following existing controller registration pattern

**New VngCloud API call:**
- Add method to interface in `internal/repository/vngcloud_repo/vngcloud_repo.go`
- Implement in `internal/repository/vngcloud_repo/vngcloud_<resource>.go`
- Regenerate mocks: `make mock` (uses mockery)

**New annotation:**
- Add constant to `internal/domain/domain.go` or the relevant `pkg/annotations/` area
- Parse in the appropriate use case via `annotations.NewSuffixAnnotationParser`

**New shared utility:**
- Cross-cutting util: `pkg/utils/<util>.go`
- Resource-specific helper: `pkg/<resource>/`

**Tests:**
- Unit tests: co-locate `<file>_test.go` next to source file
- Integration tests for use cases: add to `internal/usecase/<resource>_uc/`
- E2E tests: `test/e2e/`

## Special Directories

**`bin/`:**
- Purpose: Compiled controller binary output
- Generated: Yes (by `make build`)
- Committed: No (in `.gitignore`)

**`internal/repository/vngcloud_repo/vngcloud_mocks/`:**
- Purpose: Auto-generated mock implementations of the VngCloud repository interface
- Generated: Yes (by `make mock` using mockery, configured in `.mockery.yml`)
- Committed: Yes

**`api/v1alpha1/zz_generated.deepcopy.go`:**
- Purpose: Auto-generated DeepCopy methods for all CRD types
- Generated: Yes (by `make generate` via controller-gen)
- Committed: Yes

**`config/crd/bases/`:**
- Purpose: Auto-generated CRD YAML manifests from kubebuilder markers
- Generated: Yes (by `make manifests`)
- Committed: Yes

**`.planning/`:**
- Purpose: GSD planning documents for AI-assisted development workflow
- Generated: No (hand-maintained)
- Committed: Yes
