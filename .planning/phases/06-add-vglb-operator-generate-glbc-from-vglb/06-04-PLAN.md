**Create `internal/controller/vglb_controller/vglb_controller_test.go`:**

Ginkgo Describe("VngcloudGlobalLoadBalancer Controller") with three scenarios:

**Scenario 1: "should create GLBC from VGLB with matching NodePort Service"**
1. Create a NodePort Service `test-svc` in namespace `default` with port 80/TCP nodePort 30080
2. Create a VGLB `test-svc` in namespace `default` (same name as service)
3. Eventually (30s timeout, 1s poll): find GLBC by owner labels matching the VGLB
4. Assert GLBC spec:
   - `glbc.Spec.Name` contains `"vks_default_test_svc"` (vks_ prefix, hyphens replaced with underscores)
   - `len(glbc.Spec.GlobalPools) == 1`
   - `glbc.Spec.GlobalPools[0].Name` starts with `"pool-"`
   - `len(glbc.Spec.GlobalPools[0].PoolMembers) == 1`
   - `glbc.Spec.GlobalPools[0].PoolMembers[0].Name == "hcm-net-test-vpc"` (region from node label + VPC ID)
   - `glbc.Spec.GlobalPools[0].PoolMembers[0].Region == "hcm"`
   - `len(glbc.Spec.GlobalListeners) == 1`
   - `glbc.Spec.GlobalListeners[0].ProtocolPort == 80`
5. Clean up: delete VGLB and Service

**Scenario 2: "should delete GLBC when VGLB is deleted"**
1. Create Service and VGLB (same setup as scenario 1)
2. Eventually: GLBC exists
3. Delete the VGLB
4. Eventually: GLBC is gone (list by owner labels returns 0 items)
5. Clean up: delete Service

**Scenario 3: "should update GLBC when Service ports change"**
1. Create Service with port 80/TCP, create VGLB
2. Eventually: GLBC exists with 1 pool + 1 listener for port 80
3. Update Service to add port 443/TCP (now 2 ports)
4. Eventually: GLBC has 2 pools and 2 listeners
5. Assert one listener has ProtocolPort 80 and another has 443
6. Clean up: delete VGLB and Service

Use unique names per scenario (e.g., `"vglb-create-test"`, `"vglb-delete-test"`, `"vglb-update-test"`) to avoid conflicts.

Each scenario should use `It(...)` blocks within a `Context(...)` group and use `DeferCleanup` or AfterEach for resource cleanup.
