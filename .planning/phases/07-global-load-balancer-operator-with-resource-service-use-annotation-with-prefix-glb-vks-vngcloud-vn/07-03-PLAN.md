Test 1: "Should create GLBC when Service has glb.vks.vngcloud.vn/enable=true"
- Create namespace (unique per test to avoid conflicts)
- Create a NodePort Service with GLB annotation using `newServiceWithGLBAnnotation("test-svc", ns, []corev1.ServicePort{{Name: "http", Port: 80, NodePort: 30080, Protocol: corev1.ProtocolTCP}})`
- Wait (Eventually, 30s timeout, 1s poll) for GLBC to appear via `findGLBCByServiceOwnerLabels`
- Assert GLBC not nil
- Assert GLBC owner labels: `domain.LabelOwnerResourceKind` == `domain.KindService`, `domain.LabelOwnerResourceName` == `"test-svc"`
- Assert GLBC.Spec.GlobalPools has length 1
- Assert GLBC.Spec.GlobalListeners has length 1
- Assert pool name starts with "pool-"
- Assert listener ProtocolPort == 80
- Assert pool has PoolMembers with at least 1 member group
- Assert pool member group members have address "10.0.0.1" (the test node IP)
- Assert Service has finalizer `domain.ServiceGLBFinalizer`

Test 2: "Should update GLBC spec when Service ports change"
- Create namespace + Service with one port (80/30080)
- Wait for GLBC to appear
- Patch Service to add second port: `{Name: "https", Port: 443, NodePort: 30443, Protocol: corev1.ProtocolTCP}`
- Wait (Eventually, 30s) for GLBC.Spec.GlobalPools to have length 2
- Assert GLBC.Spec.GlobalListeners has length 2

Test 3: "Should delete GLBC when enable annotation is removed"
- Create namespace + Service with GLB annotation + one port
- Wait for GLBC to appear
- Remove the `glb.vks.vngcloud.vn/enable` annotation from the Service (patch annotations to empty map or map without the enable key)
- Wait (Eventually, 30s) for GLBC to be gone (findGLBCByServiceOwnerLabels returns nil)
- Wait for Service finalizer `domain.ServiceGLBFinalizer` to be removed

Each test should create resources in a unique namespace created with `metav1.GenerateName` to avoid cross-test interference. Use `defer` or `AfterEach` for cleanup if needed, but envtest teardown in AfterSuite handles it.
