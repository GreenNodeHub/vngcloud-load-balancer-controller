# Quick Task 260318-50e: golangci-lint v1-to-v2 Migration Fix Summary

**One-liner:** Fixed incomplete golangci-lint v1-to-v2 migration by correcting three schema-breaking field renames and committing the test file lint fixes.

## What Was Done

### Task 1: Review and fix golangci-lint v2 config migration

The uncommitted changes were reviewed against the golangci-lint v2 JSON schema. The config failed `golangci-lint config verify` with three errors. All three were fixed:

**Error 1 — `issues.exclude-use-default` and `issues.exclude-rules` not allowed**

In v2, the `issues` section no longer accepts exclusion config. Exclusions moved into `linters.exclusions`. Migrated:

```yaml
# v1 (invalid in v2)
issues:
  exclude-use-default: false
  exclude-rules:
    - path: "api/*"
      linters: [lll]
    - path: "internal/*"
      linters: [dupl, lll]

# v2 (correct)
linters:
  exclusions:
    presets: []            # presets:[] preserves exclude-use-default:false intent
    rules:
      - path: "api/*"
        linters: [lll]
      - path: "internal/*"
        linters: [dupl, lll]
```

**Error 2 — `linters.disable-all` not allowed**

Renamed to `linters.default: none` in v2.

```yaml
# v1 (invalid in v2)
linters:
  disable-all: true

# v2 (correct)
linters:
  default: none
```

**Error 3 — `linters-settings` not allowed as top-level key**

Renamed and moved to `linters.settings` (nested under `linters`) in v2.

```yaml
# v1 (invalid in v2)
linters-settings:
  revive:
    rules:
      - name: comment-spacings

# v2 (correct)
linters:
  settings:
    revive:
      rules:
        - name: comment-spacings
```
