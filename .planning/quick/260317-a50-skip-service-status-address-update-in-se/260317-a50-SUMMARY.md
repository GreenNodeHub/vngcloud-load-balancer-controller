# Quick Task 260317-a50: Skip Service Status Address Update for type=LoadBalancer

**One-liner:** Guard in `run()` skips `UpdateServiceStatusAddress` when `Service.Spec.Type == LoadBalancer` to eliminate race with the regular Service LB controller.

## What Was Done

Added a conditional early return in `defaultModelBuildTask.run()` in `build_glbc.go`. After `buildGlobalLoadBalancerConfig` succeeds, the method now checks the Service type. For `type=LoadBalancer`, it logs a debug message and returns `nil` without calling `getGLBCAddress` or `UpdateServiceStatusAddress`. For all other Service types (ClusterIP, NodePort, ExternalName), the address update proceeds unchanged.

## Decisions Made

- **ServiceGLB does NOT write to Service.Status.LoadBalancer for type=LoadBalancer:** The regular Service LB controller owns that field for LoadBalancer Services. Writing from both controllers creates a reconcile storm. The GLB address is accessible through `GLBC.Status.Domains`, so the omission is safe.
- **Guard placed after `buildGlobalLoadBalancerConfig` success:** GLBC creation/update must still complete; only the downstream status-address write is skipped.
